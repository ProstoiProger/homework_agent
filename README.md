# Homework Agent

Один Python backend для преподавателя и учеников в Telegram. Hermes, MCP, LangChain и LangGraph не используются.

## Что умеет MVP

- только преподаватель может управлять учениками, уроками и ДЗ;
- ученик подключает Telegram по персональной ссылке `/start`, после чего `telegram_id` сохраняется в SQLite;
- обычные сообщения преподавателя разбираются через Gemini или OpenRouter и серверные function tools;
- преподаватель может загрузить PDF, DOCX, TXT или MD; бот индексирует материал и генерирует ДЗ по найденным фрагментам (RAG);
- каждое новое ДЗ создаётся как PDF в статусе `GENERATED` и отправляется только преподавателю;
- approve и автоматическая отправка ученикам отключены — преподаватель пересылает PDF вручную;
- из Google Calendar синхронизируются все события ближайших 7 дней: title, дата, время, описание, место и ссылка;
- события с именем ученика дополнительно распознаются как 45-минутные уроки;
- на 43-й минуте бот напоминает преподавателю, что до конца урока осталось 2 минуты.

## Архитектура

```text
Telegram
   ↓
python-telegram-bot + APScheduler JobQueue
   ├── Gemini API или OpenRouter (понимание команды и выбор function tool)
   ├── локальный RAG: книги → фрагменты SQLite → BM25-поиск
   ├── Google Calendar API (все события на 7 дней, read-only)
   └── SQLAlchemy → SQLite
```

LLM не отправляет сообщения ученикам напрямую. Он создаёт PDF через строго описанный серверный tool, а файл получает только преподаватель.

## 1. Подготовка

Нужен Python 3.11 или новее. В каталоге проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполни `.env`:

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `TEACHER_TELEGRAM_ID` — числовой Telegram ID преподавателя;
- `GEMINI_API_KEY` — ключ Gemini API из Google AI Studio;
- `GEMINI_MODEL` — модель с function calling (по умолчанию `gemini-3.5-flash-lite`);
- `OPENROUTER_API_KEY` — необязательный ключ; если задан, OpenRouter имеет приоритет;
- `OPENROUTER_MODEL` — модель OpenRouter (по умолчанию `openrouter/auto`);
- `RESOURCE_STORAGE_DIR` — каталог исходных книг (по умолчанию `resources`);
- `RESOURCE_MAX_FILE_MB` — максимальный размер одного файла (по умолчанию 20 МБ);
- `HOMEWORK_DELIVERY_MODE` — `pdf` для красивого файла с формулами или `text` для обычного сообщения;
- `HOMEWORK_PDF_DIR` — каталог готовых PDF (по умолчанию `generated_homeworks`);
- `LESSON_DURATION_MINUTES` — длительность урока для напоминаний (по умолчанию 45);
- `LESSON_END_REMINDER_MINUTES` — за сколько минут до конца предупредить (по умолчанию 2);
- `TIMEZONE` — локальная временная зона планировщика.

Старая `homework.db` сохраняется. При запуске недостающие столбцы добавляются автоматически.

## 2. Google Calendar

Для личного календаря рекомендуется OAuth Desktop client. Если у тебя уже есть `client_id` и `client_secret`, заполни:

```env
GOOGLE_CALENDAR_ID=primary
GOOGLE_OAUTH_CLIENT_ID=твой_client_id.apps.googleusercontent.com
GOOGLE_OAUTH_CLIENT_SECRET=твой_client_secret
GOOGLE_OAUTH_TOKEN_FILE=credentials/google-calendar-token.json
GOOGLE_SERVICE_ACCOUNT_FILE=
```

OAuth client в Google Cloud должен иметь тип **Desktop app**. Также включи Google Calendar API. Если OAuth consent screen находится в режиме Testing, добавь свой Google-аккаунт в Test users.

Проверь доступ и сразу синхронизируй ближайшую неделю:

```powershell
python check_calendar.py
```

При первом запуске откроется Google OAuth в браузере. Войди в аккаунт с нужным календарём и разреши read-only доступ. После успешного входа refresh token сохранится в `credentials/google-calendar-token.json`; дальше бот обновляет доступ автоматически и браузер ему не нужен.

Команда должна вывести `Google Calendar connected`. Если календарь доступен, но события не сопоставлены, она также покажет их названия.

Альтернативно можно использовать service account: указать `GOOGLE_SERVICE_ACCOUNT_FILE` и поделиться календарём с email из JSON-ключа. Если OAuth настроен, service account не требуется.

Чтобы событие сопоставилось с учеником, его название или описание должно содержать полное имя либо псевдоним ученика, например:

```text
Математика — Дамир
```

События на весь день и события без имени ученика тоже сохраняются в недельном календаре. Для напоминаний уроком считается событие, в title или description которого однозначно найден ученик.

## 3. Запуск

```powershell
python init_db.py
python telegram_bot.py
```

При старте запускается long polling и регистрируются задачи APScheduler:

- синхронизация всех событий ближайших 7 дней сразу и затем каждые 30 минут;
- отдельное точное напоминание для каждого распознанного урока: старт + 43 минуты;
- вечерний итог в 21:00.

Интервалы меняются через `.env`.

## Работа в Telegram

Преподаватель может писать обычным языком:

```text
Добавь ученика Дамира Ахметова, 10Б, псевдоним Дамир
Дай Дамиру задачи 10–20 по производным, дедлайн завтра
Покажи ожидающие ДЗ
Покажи сгенерированные ДЗ
Покажи расписание на неделю
Синхронизируй календарь на неделю
```

## Ресурсы и генерация ДЗ (RAG)

Отправь боту документ обычным вложением от аккаунта преподавателя. Поддерживаются:

- PDF с текстовым слоем;
- DOCX;
- TXT и Markdown;
- файлы размером до `RESOURCE_MAX_FILE_MB`.

Бот извлечёт текст, разобьёт его на фрагменты и сохранит локальный поисковый индекс в SQLite. Повторная загрузка того же файла распознаётся по SHA-256 и не создаёт дубликат. Сканированные PDF без текстового слоя требуют предварительного OCR.

После загрузки можно написать:

```text
Покажи загруженные ресурсы
Сгенерируй Дамиру 8 задач среднего уровня по производным по ресурсу #2
Возьми из учебника тему квадратных уравнений и подготовь ДЗ для Алины без решений
```

Перед созданием такого ДЗ агент обязан вызвать `search_resources`. Найденные фрагменты возвращаются модели вместе с именем файла и страницей/номером фрагмента. Итог сохраняется в статусе `GENERATED`, а PDF получает только преподаватель.

## PDF с математическими формулами

По умолчанию включён `HOMEWORK_DELIVERY_MODE=pdf`. После создания ДЗ бот сразу присылает готовый PDF преподавателю. LaTeX внутри `\(...\)`, `$...$`, `\[...\]` и `$$...$$` рендерится как нормальная математическая формула. Бот никому больше файл не отправляет — преподаватель пересылает его вручную.

Чтобы временно вернуть старую текстовую отправку:

```env
HOMEWORK_DELIVERY_MODE=text
```

Команды управления:

- `/resources` — список загруженных материалов;
- `/resource_delete ID` — удалить материал и его фрагменты;
- чтобы загрузить ресурс, просто отправь файл боту.

При добавлении ученика бот возвращает персональную ссылку. Ученик открывает её, нажимает Start, и его Telegram ID связывается с записью. Повторно привязать тот же код к другому аккаунту нельзя.

Есть и детерминированные команды:

- `/homeworks` — последние сгенерированные ДЗ;
- `/pending` — старый алиас `/homeworks`, сохранённый для совместимости;
- `/sync` — синхронизировать ближайшие 7 дней;
- `/week` — синхронизировать и показать расписание недели;
- `/today` — показать сводку за сегодня;
- `/students` — список учеников.
- `/resources` — список книг и материалов;
- `/resource_delete ID` — удалить ресурс.

## Автоматическая отправка отключена

Инструменты `approve_homework` и `send_homework` удалены из LLM. Даже прямой серверный вызов `approve_homework()` или `send_homework()` завершается отказом. Единственный автоматический получатель сгенерированного PDF — Telegram ID преподавателя.

## Развёртывание

На VPS достаточно одного процесса `python telegram_bot.py` и постоянной директории для `homework.db`, `.env` и OAuth token/service-account JSON. Для production запускай процесс под systemd или другим менеджером процессов и ограничь права чтения этих файлов.
